# 持续开发路线

## 当前纵向版本

多用户与管理员、项目隔离、文本资料入库、持久化索引、LangGraph 有界检索、Tavily 搜索、兼容 OpenAI 的模型接口、任务事件、证据与报告、版本保存和下载。

## 下一阶段：研究质量

- 为已接入的语义 embedding API 增加重排器、索引任务进度与模型维度校验工具；现有命名空间按供应商与模型隔离，配置变更在重启后补建。
- 建立双语评测集，对比固定 RAG、补检索闭环、自评估关闭及长期记忆关闭，评估引用支持率、覆盖率、成本与延迟。
- 人工可编辑大纲、逐节覆盖矩阵、逐条冲突卡、逐论断引用支持审核。当前引用检查只验证编号存在，不保证语义蕴含。
- PDF OCR、复杂版式与表格解析按独立解析器接口加入；来源定位保留不可变版本。

## 下一阶段：协作与部署

- PostgreSQL + 独立任务队列，实现多进程并发、可恢复节点 checkpoint、任务租约和用户配额；当前为单后端进程/双研究线程。
- 工作区成员与细粒度项目共享权限；目前每个用户的数据完全独立，管理员不具有隐式原文读取权限。
- 部署 HTTPS 反向代理、Secure cookie、分布式限流、注册邀请或审核、审计日志、密码重置和备份恢复演练。
- 增量资料版本、索引修复命令、任务用量计费、报告版本比较及恢复界面。

## 架构约束

API 路由只做校验、授权与调度；文档解析、检索、模型和搜索封装为服务。新供应商遵守 LanguageModel/SearchProvider 协议。不得把外部调用失败变成模拟成功，不得跨项目使用任务记忆。任何数据库变更必须增加 Alembic revision，不修改已发布迁移。
